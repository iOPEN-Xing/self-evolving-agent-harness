## 源码与表达怎样逐步核对

自进化专题沿 ORD-A2 的 processing 与 channel_acceptance 两个字段，查到 POLICY 提供的内部队列规程，再沿学习实例、原生后台、候选内容、独立执行与采用切换阅读。ORD-A1 提供缺少受理条件的反例。每个阶段列出实际函数与证据文件，源码符号由 [chapters.json](chapters.json) 绑定。

文档明确区分 SKILL.md 文件哈希与整树哈希，解释它们在 TaskRun、CandidateBundle、EvalReport 和 AdoptionDecision 中的用途。共享复测分别记录正式组和候选组；同题回答变化需要继续做业务判断。相同订单的新问法与独立新订单的覆盖范围也分别保留。

机械检查保护路径、符号、单元 ID 和可发布链接，中文机制解释则由实际调用与数据读写复核。它们共同约束文档对应关系，不能仅凭契约通过判定算法效果。

## 验证

文档检查的三个新回归先在旧实现上失败，再通过修复：限定类归属的符号、遗漏的跨章 guide、仅本机存在的链接。`make verify` 包含源码及 Notebook 编译、数据与脚本语法、Ruff、文档契约和全套离线回归。

本次本地离线回归为 144 项通过。单独执行 Capstone 的 `run_assembly_light.py verify`，44 项付款/队列评分自测通过，无模型调用。章节契约覆盖 23 章与 3 组扩展，新增 1 份自进化专题；实际契约数与链接数由检查器输出，不将文档数字作为验收条件。

远程 CI 在 Ubuntu 24.04 / macOS 14 执行相同离线检查。应按分支提交 SHA 查看 Actions；课程的已执行 Notebook、Memory 与付款 Eval 仍引用此前原始运行摘要，本次文字和检查器改动没有将它们改写成新的模型实验。
