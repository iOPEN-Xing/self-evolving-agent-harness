# 文档与 DeepSeek 接入整理计划

本页保留迁移整理的范围与验收设计，执行结果归档在 [633dc89 验证记录](DOCUMENTATION_VALIDATION.md)，当前逐份内容复核见 [文档复核](DOCUMENTATION_AUDIT.md)。文档说明必须能在代码、数据和输出协议中找到依据。历史 GLM 运行记录保留原始来源，不作为 DeepSeek 的验证结果。

| 顺序 | 交付 | 验收依据 |
|---|---|---|
| 1 | 官方直连配置、API 探针、Notebook 原生 Responses 路径 | 离线配置测试；真实 Chat / Responses 调用，失败如实记录 |
| 2 | 01–09 章：运行、控制、上下文、规则、压缩、分叉、技能、披露、隔离 | 每章对应 Notebook 单元、构造材料、真实请求或工具回执；不将静态检查称为运行成功 |
| 3 | 10 章机制桥接；11–17 章：复盘、Memory、Session、Provider、Skill、Curator | 区分主线与补充实验；逐项核对触发、持久化、候选与使用的不同证据 |
| 4 | 18–23 章：业务评分、数据集、离线优化、采集、共享、装配 | 明确独立评分、数据划分、真实运行组件与自建适配器；检查发布与回滚边界 |
| 5 | Assembly、Capstone、快照附录、根目录导航及运维说明 | 运行命令、路径、业务字段、输出来源互相对应；每条主线都能进入代码 |
| 6 | 全章交叉检查、离线验证、选定真实案例、提交及远程核对 | 链接/代码入口检查；`make verify`；记录运行条件与未覆盖项；远程提交和 CI |

章节采用共同的阅读顺序，但案例和机制按实际实现展开：要解决的问题、前置知识、数据与过程、代码阅读、运行与证据、失败分支、工程应用与下一章。运行报告单独记录，章节不写死模型随机产生的工具次数或通过率。

内容验收要检查解释能否支撑判断：读者能否说清机制改变的对象，沿案例推出正确条件，再用反例说明为什么不应采用另一种判断。命令、表格和状态名是定位工具，不能替代这些推理。相同结构下仍需为每章选择符合源码的知识重点。

表中范围不等于全部付费路径已完成。迁移轮执行了选定真实案例，其余路线按验证记录保留未覆盖状态；后续文档或离线检查通过不会追加真实模型结果。

模型统一为 `deepseek-flash`，默认服务地址为 `https://api.deepseek.com`，凭证只使用环境变量 `DEEPSEEK_API_KEY`。配置与观察服务局限于课程进程，避免修改使用者的全局 Codex / Hermes 设置。
