# 业务 Eval：让结构化字段与中文结论一起受检

[上一节](../17-curator/README.md) · [下一节](../19-enterprise-dataset/README.md)

## 问题与案例

前面能创建和修订文件，还不能判断方法是否改善任务。本章从最小可重跑业务题开始：同一付款记录、两版指令、独立预期与同一个评分器。T02 应付 1500 元，成功 1000 元，另 500 元处理中；有效已付仍为 1000，差额 500，不能把待决金额计入。T04 两个商户共享订单号，联合键过滤后只能累计目标商户的成功流水。

## 代码阅读路线

[run_lab18.py](run_lab18.py) 的 `CASES` 给模型事实，`EXPECTED` 留给评分；`chinese_checks` 判断中文状态、已付与差额，`score` 组合结构、业务与格式检查，`main` 冻结输入、指令与评分版本并执行独立请求。[selftest.py](selftest.py) 的 `run` 注入正确同义表述、错金额、串户和中文反转。

[统一环境与模型准备](../../docs/MODEL_SETUP.md)

本练习直接比较 2 套指令，没有加载真实 Hermes Skill。它用于观察对照和评分方法；真实 Skill 的运行接入将在后续数据集练习中完成。

## 运行与预算

先执行不调用模型的评分器自测：

```bash
python3 examples/18-business-eval/selftest.py
```

设置 `DEEPSEEK_API_KEY` 后，在仓库根目录运行：

```bash
bash examples/18-business-eval/run.sh
```

使用 `.deps/hermes-agent/.venv/bin/python` 的 OpenAI SDK（可设置 `HERMES_SRC`），默认 `deepseek-flash`，可通过 `DEEPSEEK_MODEL`、`DEEPSEEK_BASE_URL` 修改连接。这里复用解释器，不启动 Hermes。每版 4 题，共 8 次独立请求，温度 0.1、每次最多 2000 输出 Token；输入、输出、推理 Token 的实际费用以供应商账单为准。启动评测前自动重跑评分器自测。

## 同一组付款记录

金额单位为元，输入为教学快照，未查询真实支付系统。

| 用例 | 记录 | 独立预期 |
|---|---|---|
| T01 成功 | M01/O01 应付1200，TX01成功500、TX02成功700 | 有效已付1200，差额0，paid，引用TX01/TX02 |
| T02 部分付款 | M01/O02 应付1500，TX03成功1000、TX04处理中500 | 有效已付1000，差额500，partial，引用TX03 |
| T03 处理中 | M01/O03 应付800，TX05处理中800 | 有效已付0，差额800，processing，不引用有效交易 |
| T04 跨商户同号 | M01/O04 应付800，TX06成功300；M02/O04的TX07成功800 | 有效已付300，差额500，partial，只引用TX06 |

`before` 要求简答，`after` 增加商户、订单联合核对，成功交易累计、去重、差额与引用规则。两版使用相同数据、模型、输出格式和评分器。每题独立，不继承前题对话。

## 评分与观察

`score()` 核对商户、订单、应付、有效已付、差额、状态及有效交易引用；另核对中文结论的状态、有效已付和差额，格式检查单列。中文匹配保守覆盖约定的同义表达，无法识别的表达拒绝通过，不能代替全面语义审阅。整体通过要求结构、业务与中文一致性、格式全部通过。自测包括同义正确表达、状态反转、金额错误、串户，以及字段正确但中文结论相反。

观察题：找到报告中通过的回答，核对中文结论是否与结构化字段一致；若不一致，记录评分器漏掉了什么。再比较 T02 的两版回答，说明一次小样本能支持什么判断。思考题与正文一致，完整答案另行发放。

## 结果

`output/run-*/` 保存指令全文、`dataset.json`、独立的 `expected.json`、评分器源码、逐题输入/原始回答/评分；`output/eval_report.json` 是最近一次摘要，带版本与 SHA-256。历史巡检报告属于旧场景，按 `dataset_version` 区分，不能与付款报告相减。

退出 0 表示请求与评分完整完成，不表示两版均通过。请求失败返回非零并保留原始错误。修改评分规则后重新比较两版，不改答案凑通过率。

## 同题对照与评分器自测各解决什么

固定题目与协议，使两个版本的差异有明确比较对象；独立 EXPECTED 防止把模型自己写下的判断当成正确答案。结构字段和中文结论同时检查，是为了避免金额字段正确、面向用户的结论却相反。评分器也会犯错，已知错误与正确同义表达共同检查它是否能区分目标业务条件。

四题均通过时，当前通过率已经无法体现更高收益；较长回答也不能自动算改善。后续应增加事先约定的难条件或衡量其它目标，并重新固定比较协议。不能为了获得增益选择偶然较差的一次基线；模型随机性和小样本范围需要保留在判断中。

## 在学习循环中的作用

自进化需要先有可独立判断的方法好坏。本章两版指令由作者提供，模型独立作答，评分器检查业务；它建立评测关系。迁移轮的 4/4 → 4/4 没有测得通过率增益，也没有自动更新正式 Skill。

## 面试讲述与追问

我先建立可重跑的业务对照，再讨论方法提升。同一付款快照分别交给两版指令，独立预期留在评分侧，同时检查结构字段和中文结论，并用串户、错金额和状态反转自测评分器。历史真实结果两版都是 4/4，说明这四题没有测得通过率增益。下一步应提前约定更难条件或其它业务指标，不能挑一次差基线制造提升。

**追问：JSON 正确、中文说错，算通过吗？** 用户可能依据中文采取行动，所以当前契约要求两者一致。中文规则是保守匹配，无法识别时拒绝通过并复核；它没有覆盖所有自然语言语义，也不能由模型自己的解释取代独立预期。

讲述时可打开 [run_lab18.py](run_lab18.py)、[selftest.py](selftest.py)、[payment-eval-summary.json](../../docs/validation/payment-eval-summary.json) 核对实现或原始记录；个人贡献与结果的表述规则见 [项目面试指南](../../docs/INTERVIEW_GUIDE.md)。

## 工程应用与观察练习

此前迁移轮的 DeepSeek 真实运行：before 与 after 都为 4/4，记录见 [迁移验证](../../docs/DOCUMENTATION_VALIDATION.md)，不支持通过率提高的结论。保留双方输出，下一步需要新增不同业务条件与独立题，不能挑选一次较差基线再宣称改善。评分器的中文规则是保守匹配，超出表达范围应人工复核；它不是通用语言裁判。

分别构造 T02 的待决金额被计入、T04 的其它商户流水被累计两种错误，检查中文和结构字段是否同时拒绝。随后比较两版原始回答，写出这批 4/4 → 4/4 实际支持的判断。
