# 第22讲：在线分布式部署

主入口是原生实现 `run22.py`，通过 Hermes 原生 `skill_view` 读取方法并执行工具；旧 `shared_revision.py` 是另一接入示例，把下载的 Skill 正文加入模型输入，不是独立 Hermes 或原生 skill_view。

```bash
export GLM_API_KEY=...
.deps/hermes-agent/.venv/bin/python -B examples/22-skillclaw-shared-revision/run22.py
```

使用第21讲 README 固定的 Hermes、SkillClaw 提交及已装依赖的解释器。可设置 HERMES_SRC、SKILLCLAW_SRC。原生代理保存带反馈的来源会话，两个隔离存储分别运行一次 direct 与 validated 管线。direct 只观察发布和加载，不代表业务评测通过；validated 不启动验证工作程序，正式共享旧版仍保留。

接收端对照旧版、下载新版但加载旧版、加载新版三种情况。新增健康正常而上游异常的反分支，检查是否误把连接池变为必查。回退把旧内容作为新版本发布，随后新建接收实例、核对旧哈希并重跑相同 pool-probe。未出现预期行为也照实记，不能修改回答凑效果。

## 每轮记录

`output/lecture22/<编号>/` 保存计划、来源会话、两套管线调用、manifest 前后、各任务 messages、真实命令回执与 task-version.json。版本记录同时含演示标签、共享版本、共享内容哈希、本任务固定内容哈希与原生 skill_view 核验；下载而未加载对照的共享哈希与任务哈希应不同。`anti-branch.json` 和 `rollback-check.json` 分别保存反分支及回退后新实例复测。共享版本号递增，回退内容哈希等于旧版。

每任务150秒、最多6轮、2200输出Token，单次离线240秒、逐调用12000输出Token；无总截止。计划共1个两轮来源任务、3个接收对照、1个反分支、1个回退接收任务及2轮离线提炼；任务不重跑，原生网络层仍可能重试。费用按账单核对。缺凭证直接停止。本机多进程共享 local 后端不表示已验证跨主机故障或生产部署。

企业接入约定：每次任务启动时拉取已采用版，核对完整方法文件后固定本次任务使用的内容哈希。正在运行的任务继续使用启动时版本；拉取失败时使用本机最后一次核验通过版并记录降级原因，新版从下一次任务生效。上述缓存降级和跨主机条件是部署约定，当前演示未验收故障与生产接入。

观察题：先确认 direct 或 validated 身份，分别核对下载、skill_view 与实际调用。比较反分支，再核对回退后新实例的版本和旧版哈希；解释错误单独记，正常完成不等于业务通过。
