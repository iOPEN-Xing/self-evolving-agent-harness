# 第 11 章：从前台结束到后台复盘

[上一节](../../docs/10-learning-loop.md) · [下一节](../12-memory-revision/README.md)

## 问题与案例

第 10 章理清学习接口，本章先验证经验回流的最小触发。前台负责用户回答，后台另建受限 Agent 检查可保存的内容；两条路径不能只按一个完成状态统计。案例向前台提出偏好保存要求，再观察复盘触发、线程启动与文件变化。前台也可能先调用 memory，因此后台没有新增变化不必然是漏记。

## 代码阅读路线

[run_background_review.py](run_background_review.py) 的 `make_recorder` 包装触发和工作线程，`review_tool_results` 提取请求与返回，`snapshot_memory` 比较 MEMORY / USER 文件，`main` 建立正例与阻止触发的对照。上游入口是 agent/turn_finalizer.py、turn_context.py 与 background_review.py。

[统一环境与模型准备](../../docs/MODEL_SETUP.md)：Python 3.12、deepseek-flash、官网直连。

本练习用 Hermes `AIAgent` 观察异步复盘。前台无需等待后台工作；`daemon` 线程在进程退出时可能中止，不保证持久排队或自动重试。

## 观察什么

- 触发请求与实际线程启动分别记录，前台返回时后台是否存活按实际结果报告。
- `join(timeout=60)` 后检查 `is_alive()`：仍在运行与线程结束分别报告。线程结束不等于工具成功，工具成功也不等于本次文件发生变化。
- 工具请求及回执、失败原因、前台返回时与当前观察时点的记忆文件，保存到 `output/review_trace.json`。该文件包含本练习输入，使用教学数据即可。
- 本练习观察两个阻止触发的条件：Memory 和 Skill 自动检查同时关闭；本轮实际被中断。Memory 间隔为 0 只关闭 Memory 自动检查，Skill 条件满足仍能触发。

## 机制与范围

`agent/turn_finalizer.py` 检查最终回答、未中断以及 Memory/Skill 任一检查标记。计数在 `agent/turn_context.py`；后台工作在 `agent/background_review.py`，另建 `AIAgent`，限制执行工具，不把复盘对话写回前台。

脚本在本进程内包装后台工作函数和 `run_conversation` 以观察输入、返回和线程状态，不改 Hermes 源码。记录到的警告与异常单独列出；没有捕获到失败不能证明所有环节都成功。若后台仍在运行，本次记录是中间状态，脚本停止后续对照，避免混淆归属；退出进程可能中止该线程。

本练习隔离使用 `.hermes-home/`，前台提示明确要求记住偏好，因此前台也可能先调用记忆工具。后台不再写入可能是已有等价记忆，不能直接判断模型漏记。要观察不带明确记忆要求的自主复盘，应另按正文观察题安排任务。

## 运行

前置：Python 3.12、仓库 `.deps/hermes-agent/.venv`、模型凭证。

```bash
bash examples/11-background-review/run.sh
```

输出到 `output/run.log`。复盘耗时以本次记录为准，不给出固定秒数或预先宣布成功。若复盘很快结束，前台返回时可能已观察不到存活线程；启动与结束埋点仍可帮助核对。企业接入至少记录触发、启动、结束、工具结果与失败原因。

## 异步完成要按各自状态判断

前台和后台共享经历，却有不同的完成时点。前台交付回答后，复盘可能尚未启动、仍在调用工具，或已结束但没有值得保存的内容。一个布尔值无法表达这些差别；触发条件、线程状态、工具结果和文件变化共同说明实际进度。

无变化也需要归因：已有等价记忆是合理去重，保存失败是故障，未观察到线程结束是信息不足。服务化时应为复盘分配独立作业编号，把最终状态写入持久记录；本例的 daemon 线程只用于观察，进程退出时不提供这些保证。

## 在学习循环中的作用

本章先回答经历何时交给后台，保存动作能否在前台返回后继续观察。启动线程是学习链的入口；是否真的修订 Memory 或 Skill，还需沿工具回执与文件变化核对，下一章从明确事实修订开始。

## 工程应用与观察练习

服务化应分别记录触发、入队、启动、完成、工具失败与写入结果。daemon 线程适合本地观察，服务还需持久队列、取消句柄和幂等写入。进程退出、前台超时、后台失败分别处理；前台延迟不能代表后台写入延迟。

分别找出前台和后台的 memory 调用，按调用编号核对成功回执，再比较文件快照。若后台没有新增条目，说明是已有等价内容、未执行保存，还是观察尚未结束；仅从回答无法判定时保留为待核查项。
