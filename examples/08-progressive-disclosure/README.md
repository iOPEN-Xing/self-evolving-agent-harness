# 第 08 章：按需要加载描述、正文、参考和脚本输出

上一节：[经验技能化](../07-skill-extraction/README.md) · 下一节：[隔离与审批](../09-isolation-approval/README.md)

## 为什么不把手册一次性塞进上下文

Skill 既包含简短的能力描述，也可能引用长手册与可执行脚本。若每次全部加载，成本与干扰都会增加。本章用独立随机标记观察四类内容何时进入真实请求，分清“资源在目录里”与“资源已成为本轮依据”。

## 连接池核对案例

准备 `pool-check/SKILL.md`：先区分连接占用、等待与下游耗时，不因等待升高直接断言数据库故障。`references/window.md` 给出教学阈值：同一 5 分钟窗口，占用超过 90% 且等待超过 800ms，才进一步检查配置和慢查询。

当前样例是占用 95%、等待 1200ms。满足阈值只说明应该进一步调查，不能推出数据库故障已确认。`scripts/check_report.py` 读取模拟报告并统计字符数；它不核查引用、不评估报告结论。

## 代码与运行

入口：[workshop.ipynb](workshop.ipynb)。环境准备后运行：

```bash
.venv/bin/python -m jupyterlab examples/08-progressive-disclosure/workshop.ipynb
```

| 单元 ID | 场景 | 观察标记 |
|---|---|---|
| `lab08-reader-03` | 生成目录与资源 | META、BODY、REF、SOURCE、RESULT 各有标记 |
| `lab08-reader-05` | 普通问候 | 能力描述是否出现，正文与参考是否提前装入 |
| `lab08-reader-07` | 显式 `SkillInput` | 正文加载；尚无读取参考的需要 |
| `lab08-reader-09` | 问具体阈值 | 参考文件经过工具回执进入后续输入 |
| `lab08-reader-11` | 执行报告长度脚本 | 输出是否进入请求，源码是否另行读入 |

脚本和报告使用绝对路径，避免工作目录切换导致读错文件。参考路径来自 Skill；标记用于实验检查，不要求模型在回答里逐字引用。显式加载保证本次指定正文的条件，未验证自动匹配选择质量。

## 如何读请求对照表

先看每阶段首次请求与后续请求，不能只看最后一条：参考应在工具读取后才出现。脚本执行成功可让 RESULT 进入后续上下文，而 SOURCE 是否出现需要另查；Agent 可能主动读源码，不能一概说执行脚本不加载源码。

工具回执能证明脚本这次运行并返回字符数；数值与报告内容可单独核对，但不能将它称为“报告质量评分通过”。同样，BODY 标记出现只证明正文被发送，不证明方法被正确采用。

## 在学习循环中的作用

渐进披露让方法包按需进入任务，参考文件与执行结果也能回查来源。这里使用的是构造好的方法；后续更新 Skill 时，应将正文和支持文件共同版本化，并复查实际读取范围。

## 工程应用与练习

能力描述应写清触发场景，正文包含关键流程，参考保存长字段表或条件细则，脚本完成确定性计算。每层都应有版本与来源，并限制工具可访问范围。默认将输出作为数据，不能把参考文件中的任意文本提升为系统指令。

增加第二个无关参考文件，观察它是否自动进入输入；再修改阈值重跑，检查结论是否引用本次读取的条件。对脚本输出增加长度之外的业务检查前，应先建立独立预期与反例，不能只换一个“评分”名称。
