# 未参与生成与选择的新订单条件

本目录准备三笔不同订单，用于在候选固定后检查方法能否处理改变了金额、流水和渠道条件的任务。主练习不读取本目录，未将它用于生成、选择或同订单新问法复测。本批只准备材料，没有对这些订单运行模型。

## 为什么另备订单

主线的新问法仍对应原四笔订单，能检查措辞变化，却无法覆盖新的金额组合和状态条件。这里改变业务输入，使固定方法需要重新计算和判断。三题仍是教学小样本，结果只支持相应条件，不能代替生产泛化或统计评测。

目录已经公开，文件未被主练习读取不等于对任意 Agent 都保密。执行时必须记录候选固定时点与材料暴露范围，另建隔离任务目录，防止方法生成过程读到答案。

## 材料与字段

| 材料 | 用途 | 何时读取 |
|---|---|---|
| `inputs/NEW-101.json`、`NEW-102.json`、`NEW-103.json` | 订单、应付、交易金额和状态、部分交易的渠道受理字段及任务提示 | 只读工具提供给被测 Agent |
| `grader-only/` 下的同编号 JSON | `paid`、`valid_paid`、`difference`、`queue` 独立预期 | 执行结束后由评分侧读取 |

金额沿用主线数据的数值约定，所有计算在同一题内部完成；不要混入第 18 章的元或第 19 章的整数分数据。队列规程的来源也要明确，不能仅凭交易字段推导一个未提供的组织队列。

## 独立核查怎样接线

1. 固定候选与基线完整方法包，记录源码、模型、工具协议、采样参数和数据哈希；先不读取独立预期来继续修改方法。
2. 每题使用新进程、home 与会话，只向工具提供对应输入。评分目录另行限制读取，并用越界探针验证；仅分目录不构成隔离。
3. 保存实际加载、按本题订单查询的配对回执和原始回答。缺失、工具失败或对象不匹配要单列，不能由已有主线结果补齐。
4. 评分侧按同编号预期核对状态、有效已付、差额和当前队列建议，再以同协议比较两版。主线评分要求固定在原订单场景，本目录尚未接入现有采用控制器，需要独立适配和评分器自测。
5. 阅读结果后若再改候选，这批题已经参与开发；下一次独立验收应准备新的未使用条件，保留本次结果与暴露记录。

本页给出接入要求，没有提供已完成的运行器或通过结果。原生主线及实际函数关系见 [Capstone](../README.md) 和 [自进化说明](../../../docs/SELF_EVOLUTION.md)。
